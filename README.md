# 學習樂園：Stage 6（壞壞貓圖鑑）

## 頁面

- `index.html`：學習樂園首頁，顯示柴柴夥伴與目前共用金幣。
- `collection-menu.html`：圖鑑系列選單，可選柴柴或壞壞貓。
- `gacha-menu.html`：轉蛋系列選單，可選柴柴或壞壞貓。
- `collection.html`：柴柴收藏圖鑑、收藏彈窗與展示造型選擇。
- `shop.html`：柴柴轉蛋機、結果與最近抽獎紀錄。
- `badcat-collection.html`：獨立壞壞貓圖鑑與展示夥伴選擇。
- `badcat-shop.html`：暗夜紫紅配色的壞壞貓轉蛋商店。
- `practice.html`：練習園地選單。
- `four-digit-add-subtract.html`、`three-digit-multiplication.html`：兩種可選 10、20 或 50 題的數學練習。
- `badcat-rarity.js`、`badcat-gacha-core.js`、`badcat-app.js`：壞壞貓稀有度、抽獎和獨立收藏資料；金幣交易呼叫共用 Stage 3 API。
- `catalog-menu.css`、`badcat-collection.css`、`badcat-shop.css`、`layout-alignment.css`：系列選單及壞壞貓頁面樣式；共用版面尺寸與柴柴頁面對齊。
- `assets/shiba/`：柴柴圖片 `shiba_01.png` 至 `shiba_32.png`。
- `assets/badcat/`：壞壞貓圖片 `cat_01.png` 至 `cat_32.png`。

## 壞壞貓圖鑑與轉蛋

壞壞貓收藏與轉蛋紀錄和柴柴分開儲存，但兩個商店與數學練習使用同一份金幣。壞壞貓 01「壞壞貓」是起始收藏，不會抽中，與柴柴 01 的規則相同。一般單抽 100 金幣，重複返還 20 金幣。柴柴與壞壞貓使用相同的一般轉蛋固定稀有度機率（普通 50%、稀有 30%、史詩 15%、傳說 5%）；每次先抽稀有度，再依該系列自己的收藏狀態與連續重複修正，決定該稀有度內的新收藏或重複角色。收藏進度不會重新分配一般轉蛋稀有度權重，兩系列收藏互不影響。

每個系列各自累計連續未抽到史詩或傳說的次數，達 10 次後，下一抽按鈕會顯示「保底 · 免費轉」並使用保底抽獎：史詩 80%、傳說 20%，在該稀有度所有可抽造型中均勻抽取，已收藏造型也在候選內。保底抽免費；若抽中重複造型，仍返還 20 金幣。抽到史詩或傳說後該系列計數歸零；一般轉蛋結果與保底狀態會持久化。抽獎交易先寫入可恢復的暫存，再以唯一交易 ID 執行共用扣款與返還；重載不會重複扣款或返還。

壞壞貓稀有度分組如下：

- 普通 16 款：01、02、03、05、06、07、08、09、10、12、13、14、16、18、20、24。
- 稀有 8 款：19、23、25、26、28、29、31、32。
- 史詩 6 款：04、11、15、17、21、27。
- 傳說 2 款：22、30。

一般轉蛋機率沿用普通 50%、稀有 30%、史詩 15%、傳說 5%。保底規則另見上方說明。

壞壞貓測試收藏使用 `badcatGallery.test.v1`，正式收藏使用 `badcatGallery.v1`。兩者不另設金幣帳本；測試模式的 100,000 金幣仍只由既有 `shibaGallery.stage3.test.v1` 提供。

## 共用展示夥伴

學習樂園只維持一位全域「目前展示」夥伴。從柴柴或壞壞貓圖鑑選擇角色，都會更新首頁、練習園地和兩個答題頁。兩個圖鑑各自保留最近一次選過的本系列角色；切換到另一系列後，原系列圖鑑仍展示自己的角色並標記「上次展示」，再次選取即可設為全域目前展示。此資料隨測試／正式金幣帳本隔離保存。

## Stage 5 既有功能

柴柴抽獎先按普通 50%、稀有 30%、史詩 15%、傳說 5% 固定權重選稀有度，再在該稀有度內依收藏進度與連續重複次數判定新收藏或重複。01 原型不會抽中，也不計入 31 款抽獎收藏進度。正式帳本從 0 金幣與僅收藏 01 開始。數學練習可選 10、20 或 50 題，獎勵在整份測驗結束時結算；50 題全數答對另獎勵 100 金幣；放棄測驗會作廢該次金幣，離開或重新載入則保存進度。

## 測試帳本

`app-config.js` 的 `testMode` 預設為 `true`，供開發與驗收使用。測試帳本首次建立時給予 100,000 金幣，重載後沿用餘額。正式帳本使用 `shibaGallery.stage3.v1`；測試模式不讀取正式資料。正式發佈前必須將 `testMode` 切回 `false` 並確認測試功能已在發佈建置中關閉。這是純前端設定，不能作為防作弊措施。

## 自動化驗收

在專案根目錄執行：

```sh
node verify-stage3.cjs
node verify-stage6.cjs
```

Stage 3 驗收涵蓋柴柴抽獎與保底、遷移、數學練習金幣規則與帳本隔離。Stage 6 驗收涵蓋壞壞貓 32 張圖鑑及稀有度、一般固定稀有度出率、柴柴／壞壞貓獨立保底進度、免費保底與重複返還、共用金幣交易重載恢復、抽獎圖片揭曉後更新紀錄、商店版面和測試／正式資料隔離。
